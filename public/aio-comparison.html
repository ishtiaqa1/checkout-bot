Where this bot is better

  • No recurring bot subscription.
  • Full source visibility and complete customization.
  • Simpler setup for one personal account and home IP.
  • Visible tiled Walmart queue windows make recovery understandable.
  • Good safety foundations: dry run, order guards, circuit breakers, readiness checks, watchdog, and phase telemetry.

Where commercial AIOs are better

  • Dedicated Target Shape login and ATC-cookie workflows.
  • Proven account/profile/proxy routing throughout every checkout task.
  • Integrated/server-side monitor feeds and mature retailer modules.
  • Production 2FA, CAPTCHA, queue-proxy rotation, scheduling, and account matching.
  • Continuous updates and support when retailer behavior changes.
Do we have a real chance of purchasing? Yes—on Target, a warm verified session reached checkout review in a measured p50 of 3.70 s and p95 of 3.98 s, so the bot is fast enough to compete for ordinary and moderately limited stock. That is not a guaranteed order: inventory can disappear, Target can re-challenge the account, payment can fail, and the 30-run gate stopped before placing an order. On Walmart queue drops, the bot has credible queue-entry mechanics, but the retailer controls queue position and no live queue-drop sample has been measured yet.

What is genuinely implemented

Strong current features

  • Layered Target detection: RedSky batch API, confirmation, DOM observer, and drop sweeps.
  • Target cart API “blitz,” direct checkout navigation, and UI fallback.
  • Walmart parallel activation, join mutex, event-driven queue awareness, no reload while queued, and same-page handoff.
  • Separate account profile/CDP/proxy session primitives for up to five accounts.
  • Order deduplication, per-account lock, circuit breakers, telemetry, and safe watchdog actions.
  • Dry-run/manual modes and an AI stall assistant prohibited from placing orders itself.

Important limitations

  • There is no mature Shape-cookie harvester, automatic proxy health/rotation layer, or production paid CAPTCHA/2FA provider yet.
  • Tests validate guards and dry-run paths, not a contested real order.
  • Target cart keys and purchasable variation TCINs are captured dynamically, but retailer API/DOM changes can still force UI fallback until selectors are updated.
  • Restart-safe telemetry is capped at 250 runs; repeat the gate after major retailer changes.
  • Transient OOS attempts and passkey/email verification can still interrupt runs; invalid samples are excluded from the readiness percentiles.
